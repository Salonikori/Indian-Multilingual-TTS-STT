# Hard-rules audit — 2026-09-29

## Scope and limitation

No `CLAUDE.md` existed in the supplied working tree before this audit. A current project contract was added at `CLAUDE.md`; this report audits the present source against that contract. The audit is source-level only because Gradle, Android SDK, ADB, the official sherpa-onnx AAR, and a physical Android device are absent from this environment.

## Evidence and interpretation

1. **Networking:** `app/src/main/AndroidManifest.xml` declares no `android.permission.INTERNET`. Runtime source has no `java.net`, `javax.net`, HTTP URL connection, OkHttp, Retrofit or Ktor client calls. `BluetoothClassicTransport.kt` uses Android Bluetooth Classic RFCOMM APIs by design. Gradle plugin/dependency repositories are build-time infrastructure and are not runtime app networking. No optional model downloader exists.
2. **Text-only transport:** `MessagePayload` fields are version/type/message ID/sequence/sender ID/language code/timestamp/text/ACK ID. `PayloadSerializer` serializes that metadata as UTF-8 JSON. `Transport.send` accepts a `MessagePayload`; no audio sample array, WAV, PCM, audio file or raw-audio field is present. The transport's framing `ByteArray` contains the serialized JSON payload, not recorded audio. This is a static source contract; no packet capture was run.
3. **Single active language:** `LanguageManager.loadLanguage(spec)` invokes `release()` before resolving and constructing the selected spec's STT/TTS models. Engine construction is confined to `LanguageManager`. The launcher exposes only Hindi/English selectors; the Languages screen is a status catalog, not a model loader. This supports the source-level invariant but is not a native heap/device proof.
4. **Dead code removed:** removed the unused private `createVad` compile-time helper from `MainActivity.kt`, its unused sherpa VAD imports, unused model imports, and the `vadLoaded` boolean that was always false. The smoke screen now states directly that VAD integration is not implemented there.
5. **Unfinished work made explicit:** see the `Not implemented` section in `README.md`, and `DEMO.md` gate. In particular, the live speech-to-Bluetooth-to-TTS pipeline and UI-driven pairing are not implemented as an integrated flow.

## Dependency review

Declared direct dependencies are AndroidX Compose/Activity/Core/Lifecycle, Kotlinx Coroutines Android, and JUnit for tests. There is no declared HTTP client/Firebase dependency. The sherpa-onnx AAR is conditionally included only if a local `app/libs/sherpa_onnx.aar` exists; it is absent here. A resolved Gradle dependency tree/SBOM could not be generated because Gradle and its wrapper are absent.

## Follow-up remediation

- `UtteranceSegmenter` had an unresolved `ArrayDeque.addLast` compile error under the Kotlin compiler used for the pure-source check. It now explicitly imports `java.util.ArrayDeque`.
- The zero-pre-roll configuration previously dropped the first speech frame. A regression test was added.
- `ConversationStateMachine.outgoingFinished()` previously left queued inbound messages waiting after an outgoing transmission. It now starts the next queued message and gates the microphone in phone mode; a regression test was added.
- Language switching now releases the old engine off the UI thread, with selection disabled during cleanup. The model loader validates transducer decoder/joiner files and TTS data directory, and cleanup also runs on native linkage failures.
- The Languages screen now distinguishes a complete installed pack from missing assets and unvalidated installed assets.
- APK packaging retains license/notice resources instead of excluding them.

Validation performed after these changes: pure Kotlin compilation/smoke checks for PTT/phone transitions, queued inbound playback, and zero-pre-roll segmentation; Python bytecode compilation; benchmark script `--help` checks; synthetic-fixture smoke tests for corpus preparation and TTS score aggregation; hard-rules source audit. These do not validate Android APIs, sherpa-onnx API compatibility, APK build, or physical devices.
